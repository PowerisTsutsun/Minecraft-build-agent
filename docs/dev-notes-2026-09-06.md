## What now exists

### Minecraft 26.1 sandbox (mineflayer bot, port 25566)
- `!build /<name>` places a downloaded blueprint. `!build list`, `!build menu`
  show what there is. Names live in `schematics/aliases.json`, re-read per
  command, no restart needed. A value may be a file or `template:<name>`.
- Builds land on the **requester's crosshair** (the aimed-at block becomes the
  build's minimum corner). `at <x> <y> <z>` overrides; `~` allowed.
- `!remove` takes any recorded build back out and restores the terrain under it
  (`!remove list|last|<name>`, or the build you stand in/look at).
- `.litematic` files load (`src/building/litematic.js`), alongside `.schem`
  and `.schematic`.
- Templates carry entities and container contents via `setup.txt`.

### Minecraft 26.2 (live + test) — rcon path, no mineflayer
mineflayer **cannot** connect to 26.2: `minecraft-data` 3.116.0 still stops at
26.1. Everything that actually builds is slash commands, so the rcon path
sidesteps the version problem entirely. All 334 distinct block names across our
schematics are valid on 26.2 (verified read-only against the live server).

- `src/rcon/client.js` — RCON protocol client. ~1 ms per round trip.
- `src/rcon/build.js` — fills, reusing the proven boxing/splitting/phase order.
- `src/rcon/world.js` — player position/rotation, crosshair raycast, ground find.
- `src/rcon/anvil.js` — reads blocks straight out of region files, because **RCON
  has no command that reports what block is at a position** (`/execute if block`
  only tests a guess, and structure blocks cannot be triggered by redstone).
  Note 26.2 moved regions to `world/dimensions/minecraft/overworld/region`.
- `src/rcon/journal.js` — what was placed, so it can be cleared again.
- `tools/rcon-build.js` — build a blueprint at coords or at a player's crosshair.
- `tools/rcon-export.js` — capture an existing build near a player, auto-detecting
  the structure, and register it as an alias. This produced `/house7`.
- `tools/rcon-bot.js` — the chat-driven bot: tails the server log for
  `<Player> !build ...` and answers with `/tellraw`.
- `rcon-servers.json` — targets. Logs and worlds are mounted **read-only** into
  the bot container (see `compose.yml`).

### Test server (`mc-test`)
Copy of the **live 26.2 world**, taken with `save-off` / `save-all flush` /
`save-on` so it is consistent. Port **25567**, rcon **25576** (password in `.env` as
`MC_TEST_RCON_PASSWORD`, rotated 2026-09-09 - the first one was committed to this
repo), `restart: "no"` so it never comes back on its own, 2 GB.
Online mode with an enforced one-name whitelist and `max-players=1`: it holds a
copy of a real world, so it is private to its owner. Offline mode was only ever
needed by the mineflayer bot joining as a fake player, and the 26.2 builder
drives the server over RCON with no player entity at all - so the offline-UUID
op dance below no longer applies here. Whitelist by the player's **online** uuid;
given a bare name the image writes the offline (name-hashed) uuid, which an
online-mode server never matches, and the owner is locked out of their own copy.

## Open issues, roughly in priority order

1. ~~**Power sources must be placed last.**~~ **Done 2026-09-09, but not the way
   this note expected.** A `POWER` phase already existed (`commander.js` phaseOf,
   phase 3, after attachables and before liquids and portals) and it was not
   enough: ordering says *when* a block lands, not whether the world may react
   while the rest of the build is still arriving. A sticky piston filled as
   `extended=true` retracts as soon as a tick runs, because the redstone that
   holds it out has not been placed yet, and its `piston_head` pops.

   The fix is `withFrozenTicks` in `src/rcon/clear.js`: `/tick freeze` for the
   clear and the fill together, `/tick unfreeze` after, in a `finally` and in the
   SIGTERM handler. Scheduled ticks and entity movement stop; block placement and
   neighbour updates (fence joins, dust shapes) keep working. Everything then
   evaluates once, against the finished structure.

   Measured on mc-test, moving parts only: `26547.litematic` 2/5 exact -> 5/5.
   `16267.schem` 26/38 -> 34/38. `4271.schematic` (all cells) 52 genuinely wrong
   -> 46. `tools/rcon-build.js --no-freeze` builds the old way for comparison.

   **What it does not fix:** a blueprint captures whichever moment the machine
   was copied in. If that was mid-cycle, the machine settles into its *rest*
   state once the tick resumes and those cells will never match the file - on
   `4271.schematic` all 12 piston heads go, and the sticky pistons pull the iron
   block in front of them into the head's cell. `verifySample` now counts
   `piston_head`/`moving_piston` separately as "settled" rather than calling them
   failures. Attachables mounted on a block the machine moves still pop, and are
   still reported as wrong, because they are. **[brain: known-bugs.md]**

2. **Rename `/shop1`.** It is not a shop: an enchanting room (table + 16
   bookshelves + 7 anvils + 2 grindstones) under a decorative bubble-column and
   dispenser tower. `/enchantroom` is honest.

3. **rcon removal only clears to air.** No command reports a block's identity, so
   nothing records the previous terrain. Upgrade path: `/clone` the region to a
   scratch area before building and clone it back to undo. **[brain: decisions.md]**

4. **`!export` is not available in chat on the rcon path** — it runs from the
   console because it reads region files.

5. **Live 26.2 server is not yet reachable by the bot.** Its rcon port 25575 is
   not published to the host, and publishing it needs a restart of the live
   container. `rcon-servers.json` has a disabled `minecraft` entry ready.
   Also decide an `allow` list first: rcon is console level, so anyone who can
   type `!build` there effectively has console rights. The bot now fails closed
   when no `allow` list is configured, so this is a decision to make, not a hole
   left open. **[brain: decisions.md]**

6. **The "already correct" skip is state-blind** (`here.name === baseName(name)`).
   A rebuild repairs a wrong *block* but never a wrong *state* (stair facing,
   portal axis). Deliberate — fence/redstone connection states are computed from
   neighbours and strict comparison would refill forever — but it means state
   damage has to be repaired on purpose. **[brain: known-bugs.md]**

7. **Cave vines / hanging plants** still fail; they need their support placed
   first and the attachable phase does not order within itself.

8. **`/goldfarm` needs a player to kill the piglins.** Its two lava blocks burn
   rejected items; the hay bales exist to let piglins survive the fall. It is
   built and spawning (700+ piglins), but produces nothing unattended.

9. **Elements drive phantom-mount.** Connected as `sda1` (NTFS, label Elements)
   but unmounted; `<external drive>` is a root-owned empty stub
   that Docker would happily write into. Mount with
   `sudo mount -t ntfs3 /dev/sda1 <external drive>`.
   Do **not** put a Docker volume or a world there. **[brain: known-bugs.md]**

## Traps found the hard way (do not rediscover)

- **`/fill X replace X` is not a block counter.** It reports only what it
  *changed*, so obsidian-replace-obsidian reads as zero, while
  nether_portal-replace-nether_portal reported 255,780 "filled" purely because it
  was rewriting every portal's axis — silently damaging 259,308 blocks of a
  finished build. Vanilla has no read-only count: use `tools/diff-region.js`, the
  rcon sampler, or a re-placement's "already there" number. **[brain: known-bugs.md]**
- **Portals fill last.** They are deleted on placement if their obsidian frame is
  not finished — 277,499 of 306,399 blocks lost that way. Frameless portal blocks
  placed by `/fill` *do* persist; ordering was the whole problem.
- **Read the world only after the chunks arrive.** Force-load the footprint and
  wait, or `bot.blockAt` answers null and a working command build silently falls
  back to walking placement.
- **Verification lags the burst.** After ~800 fills the client had not received
  the block changes and reported 240,786 phantom failures. Settle now scales with
  burst size.
- **Undo compared full specs to plain names**, so every stateful block looked like
  someone else's edit and was left standing. Compare with `baseName()`.
- **Offline-mode servers ignore `ops.json` entries carrying online UUIDs.** Op
  from rcon *while the player is connected* so it resolves through usercache.
  `deop` first, or `op` reports "already an operator" off the name match.
- **Downloaded machines carry no NBT.** Filter hoppers arrive empty, and an empty
  filter passes everything — that is why the iron farm's gold/ingots went to the
  lava and the auto-crafter "sorting didn't work". Load them in `setup.txt` with
  `data merge block`.

## Handy commands

**`docker compose restart` does not re-read `.env`.** It restarts the existing
container with the environment it was created with, so after changing a password
or any other variable the bot comes back authenticating with the *old* value and
sits in a restart loop logging `rcon auth failed - wrong password`. Use
`docker compose up -d --force-recreate <service>`. Worth knowing before you read
that error as a broken rotation.

```sh
# rcon bot for the test server (chat-driven)
docker exec -d mc-builder-bot node tools/rcon-bot.js --server mc-test

# one-off build / capture
docker exec mc-builder-bot node tools/rcon-build.js  --server mc-test --what /house7 --player <name>
docker exec mc-builder-bot node tools/rcon-export.js --server mc-test --player <name> --name <alias>

# start / stop the test server (it does not auto-start)
cd <docker dir> && docker compose up -d mc-test   # <host>:25567
cd <docker dir> && docker compose stop mc-test
```
